# RISK REGISTER

- Session: 01
- Scope: risks that can block the core release (`MASTER_PLAN.md:47-51`) or breach the budget
- Review cadence: at the start of every session; residual risk updated when a mitigation is live-tested

Scoring: likelihood and impact are **H / M / L**. "Detection signal" is what tells you
it happened — a risk with no detection signal is unmanaged regardless of its
mitigation. "Residual" is the risk that remains *after* the mitigation is
implemented **and verified**, not after it is merely written down.

## 2. Highest-priority items

Ordered by expected cost of being wrong, not by likelihood.

1. ~~**R11**~~ — **closed without a test.** CloudTrail already held the MSK API's rejection of `kafka.t3.small` from 2026-07-26. The probe built for it in Session 02 Stage A is retired. *Before building an instrument to ask AWS a question, check whether AWS has already answered it.*
2. **R2 + R3** — the MSK IAM client configuration is a single root cause behind two H/H risks. One verified smoke test from the Connect host de-risks both.
3. **R7** — the budget currently notifies **nobody**, because `budget_email = ""`. That is a one-line fix and it is the only thing standing between a forgotten cluster and a silent overrun.
4. **R4** — the lean endpoint design is the largest cost saving in the architecture and the least proven part of it. Its failure mode is a hang, not an error, which makes it expensive to diagnose late.
5. **R12** — cheap to prevent now, impossible to undo later, since MSK storage never shrinks.

## 3. Risks explicitly accepted

Recorded so a later session does not treat them as oversights.

| Accepted | Why | Revisit when |
|---|---|---|
| RPO of 24 hours (R6) | Raising Kafka retention raises broker storage, which is the dominant cost driver and unreducible after create | A demo scenario requires surviving a longer outage |
| Single-AZ Glue interface endpoint | An AZ failure stops Spark for the window; a lab does not need AZ-failure resilience, and 3-AZ costs 3× | The lab becomes a shared or demo-critical environment |
| Single-node k3s, no HA | Airflow control-plane loss costs a window, not data — DAGs are in Git and state is in S3 | `enable_eks` is turned on |
| Forked platform module (R9) | The one-state, one-destroy lifecycle is the cost control; separation would break it every window | Upstream Repo A becomes actively maintained |
| Local state until Session 02 (R8) | Bootstrapping a backend before the first apply is already the plan; the exposure window is one session with nothing deployed | Any apply happens before ADR-021 lands |
