Allowing `read_only=False` and reviewing each tool fails slowly: `retry_job`, `clear_task`, `refresh_partition` -- every addition defensible, the aggregate unbounded. So `read_only=True` stays the default, `plan_write` may write only immutable planning/audit objects, and `recovery_submit` is the ONLY class allowed to mutate -- with membership closed to a frozenset of two names. Adding a mutation is an ADR amendment, not a tool registration. Supersedes ADR-057 | [ADR-092](docs/adr/ADR-092-governed-mutation-surface-with-closed-membership.md) |
| ADR-093 | A column reference matches a name or a whole segment, never a fragment | `get_column_lineage()` tested the user's word against column edges with a SUBSTRING match, and `"in" in "closing_balance"` is True. The candidate extractor separately read the word AFTER `column|field`, which in "the BALANCE column IN EOD ACCOUNT" is the preposition. So `in` was extracted, matched clos*in*g_balance, and returned DERIVED -- not ABSENT -- and because the resolver accepts the first non-ABSENT candidate and breaks, BALANCE was never tried. The label was cosmetic; the cost was not: BALANCE is VALIDATED, DERIVED is below the bar that permits narrowing, so the flagship "repair only the affected data" scenario rebuilt whole COB dates while holding the evidence to narrow to one column and three keys. Matching is now name-or-whole-segment, filler is dropped BEFORE the lineage lookup, and both word orders are accepted for both keywords | [ADR-093](docs/adr/ADR-093-a-column-reference-matches-a-name-not-a-fragment.md) |
