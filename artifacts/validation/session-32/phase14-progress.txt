DEFECTS FOUND AND FIXED TODAY
================================================================================
1. SOURCE LAB NEVER BOOTED  (fixed, running)
   user-data `aws s3 sync` hit AccessDenied 20s after the IAM grant was created and had
   no retry, so cloud-init gave up and no database ever started. IAM propagation race, not
   a permissions gap -- the same call succeeds now. Cleared with
   `cloud-init single --name scripts-user --frequency always`.
   REPO FIX NEEDED: retry loop in user-data.sh.tftpl (drafted, not applied -- editing
   user-data REPLACES the instance and would discard the databases just brought up).

2. EMR SERVERLESS COULD NOT REACH S3  (fixed live + in Terraform)
   modules/emr_serverless SG egress allowed only the VPC CIDR. S3 and DynamoDB are GATEWAY
   endpoints: they route to the service's PUBLIC prefix list, which is outside the VPC
   CIDR, so every S3 call hung and the job died after 9 minutes without reading its own
   entry-point .py. This is risk R4 -- "lean endpoint set unproven; failure mode is a hang,
   not an error" -- now proven.
   FIXED: prefix-list egress (pl-6fa54006 S3, pl-67a5400e DynamoDB) added live AND to
   modules/emr_serverless/main.tf, matching, so the next plan shows no drift.

3. LAKE BUCKET POLICY REJECTS COMPLIANT CLIENTS  (worked around; TF fixed, live NOT applied)
   `DenyUnencryptedObjectUploads` denies any PutObject without an explicit
   `x-amz-server-side-encryption: aws:kms` HEADER. The bucket has DEFAULT encryption with
   the lake CMK, so header-less writes are already encrypted correctly -- the rule tests
   the request, not the result. EMR's log pusher does not send the header:
     AccessDenied ... logs/emr-serverless/.../job-metadata.log ... explicit deny
   WORKED AROUND without touching the policy, which is the better outcome: the JOB now
   sends the header --
     --conf spark.hadoop.fs.s3a.server-side-encryption-algorithm=SSE-KMS
     --conf spark.hadoop.fs.s3a.server-side-encryption.key=<lake CMK>
     --conf spark.sql.catalog.glue_catalog.s3.sse.type=kms
     --conf spark.sql.catalog.glue_catalog.s3.sse.key=<lake CMK>
   and EMR-managed logging replaces the S3 log push.
   modules/data_lake/main.tf now carries the `Null` narrowing for the day someone wants
   header-less clients to work; it is NOT applied live and is not required.
